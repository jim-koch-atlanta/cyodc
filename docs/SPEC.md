# CYODC — Design Spec

## Premise
The world ended; the dungeon is a galactic reality show. The player is a crawler.
Tone: Dungeon Crawler Carl-adjacent — a snarky omniscient announcer, absurd loot
with flavor text, dark comedy, achievement popups for dumb decisions. Original
setting and characters only (inspired-by, not derivative: no Carl, no Donut, no
copied proper nouns).

## Player experience
- Browser page: large scrolling text pane (the story), input box, ASCII map in a
  corner panel showing explored tiles, stats bar (HP/level/gold).
- Freeform text input, Zork-style. The DM interprets intent; unknown commands get
  an in-character snarky response, not an error.
- Sessions persist: close the tab, come back, resume mid-combat.

## Runtime agents (LangGraph nodes)
| Node | Model | Role |
|---|---|---|
| DM / router | Sonnet | Interprets input, narrates exploration, routes to sub-nodes, calls state tools |
| Combat | Haiku | Narrates combat rounds; math done by `combat.py` engine |
| Boss | Sonnet | Distinct personality per boss, phase mechanics from DB, scripted taunt hooks |
| NPC | Haiku | Merchants/tavern staff; personality card + RAG memory of past interactions |
| Worldgen | Sonnet | Between levels: themes, room descriptions, monster/loot placement written to DB |

## State model
Own schema (SQLAlchemy, works on SQLite + Postgres):
- `players` — id, name, class, stats (STR/DEX/etc as JSON), hp, gold, floor
- `inventory` — player_id, item_id, qty; `items` — name, flavor_text, effects JSON
- `levels` — floor number, seed, grid JSON (from BSP generator), theme
- `rooms` — level_id, coords, description, contents (monsters/loot/npc refs)
- `visibility` — player_id, level_id, explored-cell list (fog of war)
- `encounters` — active combat state: monster HP, round, initiative
- `story_log` — every narration turn, embedded into pgvector for RAG retrieval
  (recent N turns passed verbatim; older history retrieved by similarity)

LangGraph checkpointer: thread per player session; holds graph position and
message window only.

## Map
- Grid generated by deterministic BSP dungeon algorithm (`mapgen.py`), seeded per
  level. Rendered as ASCII in the frontend from `visibility` + `levels.grid`.
- Worldgen agent decorates rooms; it never invents geometry.

## Non-goals (v1)
No auth beyond a name + resume code. No multiplayer. No graphics. No mobile.
No monetization ever — but hard per-player daily token budgets before public deploy.
