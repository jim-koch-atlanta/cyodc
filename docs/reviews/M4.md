Here are some of my observations of the resulting generated code.

## The LLM generates **creative** content. Code owns **statistical** content.

The worldgen model is asked to invent monsters. However, it only ever creates a **name**, **flavor**, and **difficulty *tier***. It does not create actual stats (hit points, damage, armor, etc). See class `_WGMonster` in [worldgen.py](../../app/worldgen.py).

Given those values, **code** then produces the actual monster stats. From [worldgen.py](../../app/worldgen.py):

```py
                    slug = _monster_slug(floor, mo.name, i, session_id)
                    catalog[slug] = {
                        "slug": slug,
                        "name": (mo.name or "Thing")[:120],
                        "flavor": mo.flavor[:600],
                        **monster_stats_for(mo.tier, floor),
                    }
```

[monster_stats_for()](../../app/balance.py) then generates the hp, experience, and other stats.

## Structured output

The interface between a model and our code is a *validated schema*. [worldgen.py](../../app/worldgen.py) requests for Sonnet to produce structured output in the format of a `WorldgenOutput` object:

```py
out = run_structured(
    "worldgen",
    [HumanMessage(content=_skeleton_prompt(floor, dm, kinds))],
    WorldgenOutput,
)
```

We call `run_structured()` — a thin wrapper in [llm.py](../../app/llm.py) — rather than LangChain's `with_structured_output()` directly. That's deliberate: **every model call in the project funnels through one gateway** (`app/llm.py`), so model selection (which model each agent role uses), token budgets, and timeouts all live in one place. `run_structured()` builds the model there and calls `.with_structured_output(schema)` internally — keeping this call consistent with every other LLM call in the codebase.

**Note**: Interestingly, Claude originally did not use the built-in structured output functionality of LangChain's `with_structured_output()`. Instead, the worldgen agent was making a standard chat completion request, and then [attempting to extract and parse the output](https://github.com/jim-koch-atlanta/cyodc/pull/4/changes/d289f1d774db45745fe75692c48f8b3f38305928#diff-a9630750bc6df7ca8b9ed2715d2738725a2f25713a3431187ea68a494ccdd4d2R127-R128):

```py
reply = run_agent("worldgen", [HumanMessage(content=_skeleton_prompt(floor, dm, kinds))])
data = json.loads(_extract_json(message_text(reply)))
out = WorldgenOutput.model_validate(data)
```

## The LLM is never a hard dependency

Any project built heavily on AI content has to answer one question up front: **when the AI call fails, does the feature fail with it?** And these calls *do* fail — timeouts, rate limits, garbled output, a missing API key. If the answer has to be "no, the game keeps working," then the LLM can only *enhance* the experience, never *gate* it — which means every AI-dependent path needs a **deterministic fallback**.

Worldgen takes exactly that stance: any failure in the model call is caught, and we fall back to deterministic content — so descending never breaks:

```py
    try:
        out = run_structured(
            "worldgen",
            [HumanMessage(content=_skeleton_prompt(floor, dm, kinds))],
            WorldgenOutput,
        )
        return _to_floor_content(out, floor, dm, kinds, session_id)
    except Exception:
        logger.exception("worldgen generation failed on floor %s; using fallback", floor)
        return _fallback_content(floor, dm, kinds, seed, session_id)
```

## The LLM only *augments* the deterministic content

The map geometry continues to be the 100% deterministic content from the binary space partitioning from [Milestone 2](./M2.md). The new worldgen only *decorates* that:

```py
by_index = {r.index: r for r in out.rooms}     # model's output, indexed
for i in range(len(dm.rooms)):                  # iterate the AUTHORITATIVE skeleton
    wg = by_index.get(i)                        # pull the model's decoration for room i
    descriptions[i] = wg.description if wg else _DEFAULT_DESC[kind]
```

If the model misses a room, there is still a default description, so the room still exists. The LLM is just adding to the shape that was already there.
